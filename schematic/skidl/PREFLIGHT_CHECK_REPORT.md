| 版本 | 问题 | 严重级 | 后果（如果不修复） |

## 三、需注意的设计约束 (非bug)

### 3.1 3.3V功耗预算 (ME6211最大500mA)

| 负载 | 典型电流 | 峰值电流 |
|------|---------|---------|
| ESP32-S3 (WiFi+BT) | 200mA | 350mA |
| MPU6050 | 3.9mA | 3.9mA |
| LCD ST7789 (不含背光) | 5mA | 10mA |
| LCD背光 (BLK→3.3V) | **50~100mA** | **100mA** |
| SD卡 (写入) | 50mA | 100mA |
| DFPlayer (播放) | 30mA | 50mA |
| INMP441 | 1.4mA | 1.4mA |
| I2C上拉 (2×4.7K) | 1.4mA | 1.4mA |
| **合计** | **~340mA** | **~620mA** |

> ⚠️ **峰值可能超过500mA**。如果WiFi+SD卡写入+LCD背光同时工作，可能触发ME6211过流保护。
> **建议**: 软件层面避免WiFi传输+SD写入+高背光同时进行；或者未来改用更大电流LDO。

### 3.2 5V功耗预算 (PTC保险丝 Ihold=500mA)

| 负载 | 电流 |
|------|------|
| TP4056充电 (500mA) | 500mA |
| WS2812B×3 (全白) | 180mA |
| 74AHCT125 | 10mA |
| **合计** | **~690mA** |

> ⚠️ **充电+全亮LED总电流690mA超过PTC 500mA hold**。PTC在500mA~1A之间可能触发。
> **建议**: 软件层面限制LED在充电时的亮度；或改用750mA/1A PTC。

### 3.3 DFPlayer 3.3V供电

> DFPlayer规格为3.2~5V，3.3V在下限。可能出现音量较小或偶发不稳定。
> 如果遇到问题，可将DFPlayer VCC改接5V_PROT（但注意UART电平差异）。

## 四、最终结论

### ✅ 可以开始绘制原理图

经过v2.1→v2.2→v2.3三轮修复，所有芯片的：
- **引脚映射** — 严格按照各自数据手册的物理封装引脚号
- **必需外部元件** — 全部配齐（去耦、电荷泵、稳压旁路、上拉、下拉）
- **电源电压** — 全部在芯片规格范围内
- **信号电平** — 3.3V↔3.3V兼容，WS2812B经电平转换到5V
- **保护电路** — USB ESD+过流、LED电平转换、按键去抖、阻尼电阻

累计修复了 **10个致命/严重级bug**，当前设计 **0个已知电气错误**。
